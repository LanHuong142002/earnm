# Plan: People can create projects and work on them offline

Spec: `.ourkit/specs/claude-ourkit-spec-4-feature-flow-40dfbf.md` (ticket #4). Tier: Feature. Sensitive Areas: data, schema, public API.

## Approach

API: add `Project` and `ProjectMember` to the Prisma schema in one additive migration, and a `projects` router in the same style as `me/routes.ts` (dependency injection, `requireAuth`, strict zod schemas, `AppError`). Each editable field keeps its own `editedAt` column. A change is applied per field with a conditional `updateMany` (`where editedAt < incoming`), so per-field last-write-wins is decided by the database atomically, with no read-then-write race. Create is idempotent on the phone-chosen id.

Mobile: build a small, generic sync layer in `src/sync/` that knows nothing about projects. It has a persisted queue of `create | update | delete` changes, each for an `(entity, id)` pair, and merges them with entity-agnostic rules. It also has a typed registry that each feature fills with how to send each change kind, and a single-runner `flush()` triggered on change, app open, foreground and reconnect. Projects live in `src/projects/`: API calls, a persisted cache, an overlay that reapplies waiting changes after each refresh, a `ProjectsProvider` context, and the screens. Storage is AsyncStorage, reconnect detection is NetInfo, and ids come from `expo-crypto`'s `randomUUID`. All three are bundled in Expo Go, so no dev build is needed.

Add a mobile test command (vitest, as in the API) that covers the pure TypeScript modules (queue, merge rules, overlay, currency formatter) with in-memory storage and fake senders. Screens are checked by hand in Expo Go.

## Prior Art

- **In the project:**
  - The language sync in `AuthProvider.tsx` (a pending flag, a single-runner flush with a rerun flag, a retry on foreground, and `endSession` on `not_signed_in`) is the precedent for the queue. Its single-runner and rerun pattern will be reused in `flush()`, generalised from one flag to a list.
  - The API patterns are reused as they are: `createApp` DI, `requireAuth`/`getAuth`, `AppError`, the zod error mapping, `isUniqueViolation` (P2002) from `auth/routes.ts`, and the test helpers `useTestApp`, `createClock` and `expectError`.
  - A signed-in-user helper exists only inline in three test files. It will be moved into `test/helpers.ts` as `createSignedInUser()`, because the projects tests need it many times.
- **In libraries:** TanStack Query, with a persisted cache and paused mutations resumed via `setMutationDefaults`, is the closest official tool. It covers the persisted cache and per-kind senders. It doesn't cover merging waiting changes (R23), reapplying them over a refresh (R19), or keeping the queue across a 401 for the same person only (R27–28), which would be custom code around it anyway. It would also add a large dependency and a second state model next to the existing context-based one. Conclusion: **write new**, about 200 lines, modelled on the existing language flush. Revisit TanStack Query if later features need richer caching.
- **No existing formatter or uuid** in the app. Currency formatting is written by hand, not with `Intl.NumberFormat`, so the output is exactly what R16 says, whatever the device locale or Hermes's Intl data.

## Changes

### API (`apps/api`)
- `prisma/schema.prisma`:
  - Add `enum Currency { VND USD }` and `enum ProjectRole { owner member }`.
  - Add `Project { id String @id (no default; the phone supplies it), name, description String @default(""), currency, nameEditedAt, descriptionEditedAt, currencyEditedAt, createdAt, updatedAt, members }`.
  - Add `ProjectMember { projectId, userId, role, createdAt, @@id([projectId, userId]), @@index([userId]) }` with `onDelete: Cascade` to both `Project` and `User`.
  - Add `projects ProjectMember[]` to `User`.
- `prisma/migrations/<timestamp>_projects/`: generated by `npm --prefix apps/api run db:migrate`. It only adds tables, so it stays compatible with `db:deploy` on start (docs/deploy.md).
- `src/projects/routes.ts` (new), `createProjectsRouter(deps)`, all behind `requireAuth`. Responses are `{ id, name, description, currency, role }`.
  - `GET /projects`: the caller's memberships joined to their projects, ordered by name.
  - `POST /projects` with body `{ id: uuid, name, currency, description?, editedAt }`, strict:
    - In a transaction, read the project by id. If the caller is a member, return it with `200`. If it exists and the caller isn't a member, refuse with `409 id_conflict`. Otherwise create the project with all three `*EditedAt` set to the clamped `editedAt`, plus an owner membership, and return `201`.
    - On P2002 from a concurrent identical create, re-read and apply the same rules.
  - `PATCH /projects/:id` with body `{ fields: { name?|description?|currency?: { value, editedAt } } }`, strict, at least one field:
    - Not a member gives `404 not_found`, a member who isn't an owner gives `403 forbidden`.
    - For each field, `updateMany({ where: { id, <field>EditedAt: { lt: clamped } }, data: { <field>: value, <field>EditedAt: clamped } })` in one transaction, then return the project's current state with `200`.
    - Each `editedAt` is clamped with `min(editedAt, deps.now())`.
  - `DELETE /projects/:id`: a non-member gives `404`, a non-owner gives `403`, then `deleteMany({ where: { id } })`. A count of `0` gives `404`, otherwise `204`. Memberships go by cascade.
  - Validation for R1: name trimmed, 1–80 characters; description trimmed, ≤500; currency enum; id is a uuid; `editedAt` is an ISO datetime.
- `src/app.ts`: mount `app.use("/projects", createProjectsRouter(deps))`.
- `src/test/helpers.ts`: add `"Project"` to the truncate list and add `createSignedInUser(clock)`. The inline helpers in `me/routes.test.ts` stay as they are, so this change doesn't touch unrelated tests.

### Mobile (`apps/mobile`)
- Dependencies: `npx expo install @react-native-async-storage/async-storage @react-native-community/netinfo expo-crypto`, plus `vitest` as a dev dependency and a `"test": "vitest run"` script with a `vitest.config.ts` limited to `src/**/*.test.ts`.
- `src/lib/currency.ts`: `formatMoney(amount, currency)` per R16.
- `src/sync/storage.ts`: a small `KeyValueStore` interface (get/set/remove JSON), with the AsyncStorage implementation and an in-memory one for tests.
- `src/sync/queue.ts`: the generic queue.
  - A `Change` is `{ changeId, entity, entityId, kind: "create" | "update" | "delete", data, fieldTimes }`.
  - Merge rules (R23), by `(entity, entityId)`:
    - update + update: merge fields, keeping each field's latest value and time.
    - create + update: fold into the create.
    - create + delete: drop both.
    - update + delete: becomes a delete.
  - `registerEntity(entity, senders)` with `senders: Record<Kind, Sender>`, typed so a missing kind fails the type check (R22).
  - `flush()` runs one at a time with a rerun flag, sends in order, and classifies each result:
    - success or conflict: apply the server's version, remove the change;
    - `network`: stop and keep the rest;
    - `not_signed_in`: stop, keep everything, and call `onSignedOut`;
    - `403`, `404` or `validation_failed`: remove the change and call `onRejected(entity, entityId, status)`.
  - The queue is stored together with the `userId` it belongs to.
- `src/sync/triggers.ts`: subscribes to AppState `active` and the NetInfo offline-to-online transition. Each one, and each enqueue, calls `flush()`.
- `src/projects/api.ts`: `listProjects`, `createProject`, `patchProject` and `deleteProject` over the existing `request()`.
- `src/projects/store.ts`, pure functions plus persistence:
  - The cache is `{ userId, projects, currentProjectId }`.
  - `applyOverlay(serverList, waitingChanges)` handles R19: it applies waiting creates, updates and deletes on top of the server's list.
- `src/projects/ProjectsProvider.tsx`:
  - Loads the cache at once (R17), refreshes when online, and exposes `create`, `rename`, `update` and `remove`.
  - Each of these updates the cache optimistically and enqueues a change (R21).
  - It tracks `currentProjectId` and the rejected-change note (R26).
  - It registers the `project` entity senders.
- `src/auth/AuthProvider.tsx`:
  - On a user's sign-out (not on a 401), clear the cache, the queue and `currentProjectId`. Before that, the Settings screen checks the waiting count and confirms (R28).
  - On sign-in as a different `userId` than the stored queue's owner, clear them. On sign-in as the same person, flush (R27).
  - `endSession` from a 401 keeps the queue.
- Screens (expo-router, Decision 10, existing `ui/` components, DESIGN.md offline and pending notes, no tables):
  - `app/(app)/index.tsx` becomes the current project screen, with its name, currency, collapsible details, and a switcher row linking to the list (R29, R31).
  - `app/(app)/projects/index.tsx` is the project list with the empty state (R30).
  - `app/(app)/projects/new.tsx` and `app/(app)/projects/[id]/edit.tsx` are the create and edit forms. They use client validation matching R1 (R32). Edit and Delete are shown to owners only, and Delete has a confirmation that names the project.
  - `app/(app)/settings.tsx` gets the sign-out warning when changes are waiting.
- `src/i18n/en.json`, `vi.json`: a `projects.*` section and new `errors.*` codes (`forbidden`, `id_conflict`).

## Risks

- **Sensitive Areas (data, schema, public API).**
  - Access control is the main risk: every route must scope by membership. Tests cover a non-member getting `404` with the same body as a missing project, and a member getting `403`, on every route (AC 7, 9, 10).
  - The Review runs `ourkit-sensitive-reviewer`.
- **Migration on deploy:** Render runs `db:deploy` on start, and this migration is additive only. No existing column changes.
- **Race conditions:**
  - LWW uses conditional `updateMany`, not read-then-write.
  - Idempotent create handles P2002.
  - `flush()` is single-runner with a rerun flag, so a change is never sent twice at once (AC 24).
- **The 401 versus sign-out distinction:** `endSession` is used for both today. Clearing the queue on a 401 would lose offline work, and keeping it on a real sign-out would leak data to the next person. The change keeps them as two separate paths, with tests on the queue owner check.
- **Phone clocks:** the server clamps future times (R14). A phone clock that runs behind can still lose conflicts. That's accepted under last-write-wins.
- **Expo Go:** only bundled native modules work. AsyncStorage, NetInfo and expo-crypto are bundled. Install them with `npx expo install` so the SDK 58 versions match, and check the SDK 58 docs before use (apps/mobile AGENTS.md).
- **docs/roadmap.md defers conflict handling.** Epic Decision 4 and the agreed spec supersede that line. The roadmap will be updated to say last-write-wins per field.
- **Review convergence (lessons):**
  - Only correctness, security and spec gaps block. Style nits are logged as non-blocking and aren't fixed within this change.
  - Reviewers run one after another on the shared test database.

## Test Strategy

Commands: `ourkit command test` (API today, both suites after the stack-profile change), `ourkit command lint` (mobile), `ourkit command build` (API typecheck and build). The mobile type check runs through `tsc --noEmit` inside the mobile test script (`"test": "tsc --noEmit && vitest run"`), so R22's "missing kind fails the type check" is enforced by the test command.

- **API, vitest + supertest on the test database** (AC 1–15, 34): validation limits, owner on create, phone-chosen id, idempotent and conflicting create, scoped list, owner-only edit and delete, `404` versus `403`, `401` on every route, per-field `editedAt` storage, older-field ignore, independent fields, future-time clamping with `createClock`, `200` on a fully ignored change, cascade on user and project delete, and the migration applying to the test database through `migrate deploy` in global setup.
- **Mobile, vitest on pure modules** (AC 16, 19, 22–27):
  - currency formatting;
  - `applyOverlay`;
  - merge rules;
  - ordering;
  - single-runner;
  - the result classification for success, conflict, `network`, `401`, `403`, `404` and `validation_failed`;
  - the queue owner check.
- **Network failures in tests (lesson):** they are simulated by fake senders that throw `ApiError("network")`, not by real closed ports. This is decided here so Review doesn't flip it.
- **By hand in Expo Go, becoming the Test Handoff** (AC 8 note, 17, 18, 20, 21, 28–33): airplane-mode launch and refresh, the offline note, force-quit persistence, optimistic create, rename and delete, sign-out warning and switching person, the remembered project after deletion elsewhere, the empty state, the switcher, form messages and owner-only controls, using a Member row inserted with SQL since invites are #5, and both languages.
- **Not verified automatically:** real NetInfo transitions and AppState triggers on a device, and the screens themselves. These are covered by the Test Handoff.

## QA addendum: screens and navigation (approved by the user at QA)

Hand testing showed the screens didn't connect (`router.replace` everywhere, so no back control or swipe-back) and that the user wants a real Home. The spec's requirements 29–31 and 32 were rewritten (29, 29a, 29b, 30, 31, keyboard part of 32). Changes:
- `src/app/(app)/` becomes a tab layout (expo-router `Tabs`) with two tabs: Home (a nested Stack: Home, Project list, Project `projects/[id]`, New project, Edit project) and Account (today's Settings). Headers shown with the native back button; native swipe-back stays enabled.
- Home: current-project card, then a tile grid using the theme's `tile` tokens: Projects (opens the list), Ideas and Shared schedule disabled with "Coming soon".
- A new Project screen `projects/[id]` holds what Home shows today (name, currency, collapsible details, Edit for owners, Switch project).
- Moves use `router.push`; New project → Project uses `replace` so back skips the form; delete uses `dismissTo('/projects')`; a vanished current project navigates to the list. Sign-in → Home stays a guarded replace.
- Forms: `returnKeyType` next/done with focus moving name → description and submitting from the last field; keyboard-avoiding layout so the submit button stays visible.
- The rejected notice says "couldn't be created" for a refused create instead of "no longer exists".
- Tests: pure navigation helpers where logic exists; screens checked by hand (Test Handoff).
